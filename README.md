## Premium 和 Tier 1，真正差在哪里

如果你只看配置，两个系列会让人产生一个错觉：都是东京、都是 VPS、都是 AMD 平台，好像只是价格高低不同。

其实核心差别在网络。

### Premium：为中国大陆访问场景准备

Premium 的关键词是 **CN2 GIA**。DMIT 当前东京机房页面明确把它定位为面向中国大陆的优化网络，并给出了约 28ms 的参考平均延迟和低于 0.1% 的参考丢包率。这个数字不能理解成“全国任何地方都固定 28ms”，而应该理解成官方测试样本的参考值。

所以，下面这类项目更适合优先研究 Premium：

面向中国大陆访客的网站、跨境电商后台、需要频繁访问中国大陆 API 的应用、对交互延迟比较敏感的业务，以及希望东京节点同时服务中国大陆和东亚用户的部署。

Premium 价格明显更高，最便宜的 TINY 目前就是 **$21.90/月**。如果只是为了“我想要一个日本 IP”，这个价格未必合理；如果业务真正依赖中国大陆访问质量，线路才是需要花钱的地方。

### Tier 1：把钱花在更便宜的国际互联上

Tier 1 没有中国大陆专属优化，官方定位就是 APAC、北美、欧洲之间的国际低延迟互联。最低公开档位是 **$6.90/月的 TINY**，还有 **$36.90/年的 WEE**，价格门槛和 Premium 完全不是一个量级。

这条线更适合日本本地业务、亚太区域应用、海外测试环境、备份、开发机，或者本身已经有中转节点、不要求 VPS 直接承担中国大陆终端访问的项目。

它还有一个实际优势：流量容量明显大于 Premium。比如 Tier 1 MICRO 当前显示 **4 vCPU、4GB 内存、80GB SSD、16000GB Max (IN/OUT)**，而 Premium MICRO 是 **4 vCPU、4GB、80GB、4000GB**。如果项目本身吃流量，价格与额度的差异会迅速拉开。

## 流量不够，会发生什么

这是买 VPS 时经常被忽略的部分。

Tier 1 产品当前公开页面使用的是 **Max (IN/OUT)** 的传输额度展示，而且不同档位额度非常大，从 TINY 的 2000GB 到 GIANT 的 128000GB。对于需要跑大量备份、镜像、跨区域同步或其他高流量任务的人，这个指标应该和 CPU、内存放在同一优先级考虑。

Premium 当前公开页面展示的是固定传输额度，例如 TINY 500GB、STARTER 1000GB、MINI 2000GB、MICRO 4000GB、MEDIUM 6000GB、LARGE 8000GB、GIANT 15000GB。不要因为端口写着 1Gbps 就误以为“每个月可以随便跑满 1Gbps”，端口速率和传输额度是两个概念。

这也是为什么低价 Tier 1 方案在某些任务里反而更适合：它不是 Premium 的“缩水版”，而是把网络优化预算压低，再给你更多传输额度。

## 硬件够不够用

东京当前使用的 AS3 平台基于 **AMD EPYC 7003**，配合 NVMe 存储。官方定位是覆盖网站、开发环境以及一般云工作负载。

对于普通 WordPress、小型 API、个人项目、监控、开发测试，这种规格已经足够让选择重点回到网络和流量，而不是盯着“是不是最新一代 CPU”。

而不是反过来。
